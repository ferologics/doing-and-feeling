How does a transformer work?
Here's the picture an engineer would draw.
Text is split into tokens, roughly words or pieces of words.
Each token becomes a vector, a list of a few thousand numbers,
and these vectors flow up through dozens of layers along the residual stream,
a shared channel that each layer reads from and writes back to.
Each layer has two parts.
The attention mechanism lets each position look back at earlier positions and pull in information.
Each position emits a query.
every earlier position offers a key and a value, and the match between query and key
sets how much of each value is mixed in. That's how a model works out which noun a pronoun refers to
or tracks a variable through a program. The second part, a feedforward network,
transforms each position on its own and appears to store much of the model's associative knowledge.
At the top, the model outputs a probability distribution over the next token.
Training nudges every weight to make the actual next token more probable,
which, as we saw in episode 3, is the same as minimizing the bits needed to encode the text.
A language model is, quite literally, a compressor.
When it generates, it samples a token, appends it, and runs again,
reusing a key value cache of its earlier computations.

is a question we'll take up in Episode 12.

Do these systems understand? The debate has a clear history.
In 1990, the cognitive scientist Stevan Harned posed the symbol grounding problem.
Imagine trying to learn Chinese from a Chinese-to-Chinese dictionary.
Every symbol is defined only by other symbols, and you never get off the merry-go-round.
In 2020, Emily Bender and Alexander Collar updated it with the octopus test.
